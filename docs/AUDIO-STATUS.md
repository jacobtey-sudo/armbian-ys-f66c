# Звук YS-F66C (rk809) под Armbian

## Работает
- Микрофон платы: захват через `Capture MIC Path = Main Mic`. Сигнал клиппит — снизить `ADC PGA Gain` / `MIC Boost Gain`.
- Запись с BT-гарнитуры (HFP): проверено, речь записана.
- Воспроизведение BT: HFP работает. A2DP на K12 работает (планшет исправен). У BW-HP2 A2DP молчит — проблема гарнитуры.
- Динамик платы: работает.
- Наушники 3.5 мм (путь HP): работают.

## Правки DTS (узел `rk809_codec` в `rk3566-ys-f66c.dts`)
- `out-l2spk-r2hp;` — без него на пути SPK драйвер выключает DAC L/R (`ADAC_CFG1=0x03`), звука нет.
- `spk-ctl-gpios = <&gpio2 RK_PC6 GPIO_ACTIVE_LOW>;` — усилитель динамика на GPIO2_C6, активен низким уровнем. Было ошибочно `gpio3 PA5 GPIO_ACTIVE_HIGH`.

## Jack detect и автоматическое выключение динамика

Проводные наушники определяются через `rk-headset` (GPIO3_D1, pinctrl
`hp_det`). В DTS добавлены узел `rk_headset` и pinctrl с pull-down; полярность
совпадает с Android: при вставке GPIO читается высоким.

`ys-f66c-headset-route` слушает extcon и переключает codec:

- наушники вставлены: `Playback Path=HP`;
- наушники извлечены: `Playback Path=SPK`.

В пути `HP` codec снимает `spk-ctl` (GPIO2_C6, active-low), поэтому динамик
молчит. Проверено на 50% громкости: при вставке звук остаётся только в
наушниках, после извлечения возвращается в динамики.

Особенность драйвера `rk817`: смена `Playback Path` при уже играющем PCM-потоке
не обновляет `spk-ctl`; GPIO меняется только в `rk817_digital_mute_dac()` при
старте/остановке потока. Поэтому сервис после смены пути кратко усыпляет и
будит аналоговый sink (`pactl suspend-sink`). Если в будущем будет принят
патч codec, обновляющий `spk-ctl` прямо в `rk817_playback_path_config()`, этот
обход можно убрать.
